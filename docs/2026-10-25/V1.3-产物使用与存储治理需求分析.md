# CrawlerHub V1.3 需求分析：产物使用与存储治理

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1（评审稿） |
| 产品版本 | V1.3 |
| 编写日期 | 2026-10-25 |
| 文档类型 | 版本需求分析，非开发排期承诺 |
| 需求来源 | 现有 PRD 的 P2-04/P2-05、产物页实现及 2026-10-25 产品迭代分析 |
| 核心主题 | 用得上：让采集结果可预览、可整理、可交付，并控制重复文件与存储占用 |

## 1. 背景与问题定义

V1.0 的产物页已支持组合筛选、打开目录、失败重下和删除，但主要承担“文件账本”角色。用户仍需离开产品才能判断内容是否可用，也缺少批量处理、同名冲突治理和存储管理能力。

V1.3 的目标是把主链路从“采集成功并落盘”延伸为“确认内容可用并完成后续使用”，同时确保自动采集规模扩大后，产物账本、磁盘文件与用户预期保持一致。

### 1.1 现状证据

- 产物列表展示名称、类型、状态、大小、路径和时间，没有视频、文字或图片预览。
- 当前仅提供单条操作，缺少批量重下、删除和元数据导出。
- 同名产物默认覆盖并写 WARN，内容指纹去重和版本化尚未完整产品化。
- 临时目录、历史失败产物和长期自动采集会增加存储压力，现有首页没有产物存储视角。
- V1.2 引入自动采集后，重复文件、无人处理的文件缺失与磁盘占用会更明显。

### 1.2 关键假设

- 本地文件仍是唯一权威产物，云同步和对象存储不在本版本范围。
- 浏览器预览是本地文件的便捷消费方式，不能改变原文件格式或自动转码全部历史文件。
- 所有清理与批量删除必须可预检、可确认、可审计，不以后台静默删除替代用户决策。

## 2. 版本目标与成功指标

### 2.1 产品目标

1. 用户无需离开产品，即可判断常见视频、文字、PDF 和图片产物是否满足使用要求。
2. 用户可以安全地批量处理失败、缺失和不需要的产物，并导出可交付清单。
3. 重跑同一内容时，重复、覆盖和版本化行为可预期，不再默认无声覆盖。
4. 用户可以了解存储占用，并通过预检后的清理规则释放空间。

### 2.2 核心指标

| 指标 | 定义与口径 | 建议目标 | 排除项与说明 |
| --- | --- | --- | --- |
| 产物使用率 | 自然周内至少被预览、打开目录或导出一次的产物数 ÷ 当周成功产物数 | 建立基线后提升 | 自动健康检查不计为使用；同一产物多次使用只计一次 |
| 预览成功率 | 成功加载首帧/首屏的预览次数 ÷ 发起预览次数 | 建议 ≥95%（仅浏览器支持格式） | 不支持格式单独展示，不计入分母 |
| 重复产物冲突率 | 同名但指纹不同的冲突产物数 ÷ 成功产物数 | 建立基线后下降 | 明确选择“保留版本”的不计为异常 |
| 账实一致率 | 抽查中数据库状态、路径、文件存在性与类型一致的产物数 ÷ 抽查产物数 | 建议 ≥99% | 外部正在移动的文件记为待确认，不强行判成功 |
| 存储清理完成率 | 预检后成功完成且未影响活跃任务的清理批次数 ÷ 已确认清理批次数 | 建议 ≥99% | 用户取消不计入分母 |
| 批量操作误恢复率 | 批量删除/清理后在 24 小时内通过重下或恢复操作补救的批次数 ÷ 批量操作批次数 | 先观察，不作为单独惩罚指标 | 用于发现误操作与文案问题 |

> 最小数据能力：提供本地产物使用与存储看板，至少展示使用次数、文件缺失、重复冲突、类型占用、临时文件占用和清理结果。

## 3. 目标用户与核心场景

| 用户 | 核心诉求 | 典型场景 |
| --- | --- | --- |
| 内容运营 | 快速检查内容并交付清单 | 预览图片与文字，筛选后导出 CSV/JSON 清单 |
| 个人采集者 | 批量整理失败与缺失文件 | 选择失败产物统一重下，对缺失文件定位修复 |
| 技术维护者 | 控制长期采集的重复与存储成本 | 配置去重和同名策略，预检临时文件清理结果 |

### 用户故事

- 作为内容运营，我希望直接预览产物，以便确认采集结果是否正确。
- 作为个人采集者，我希望批量重下失败项，以便减少逐条处理成本。
- 作为技术维护者，我希望在清理前看到影响范围和预计释放空间，以便避免误删。

## 4. 需求范围

### 4.1 本版本包含

- 视频、文字、PDF 和图片的本地预览与不支持格式降级。
- 产物多选、批量重下、批量删除与清单导出。
- URL 规范化、内容指纹、同名冲突与保留版本策略。
- 文件缺失检测、重新定位和修复入口。
- 存储占用看板、临时文件清理与保留规则预检。
- 批量操作审计与本地使用指标。

### 4.2 本版本不包含

- 云端同步、对象存储、在线协作与多人权限。
- 全站视频转码、格式转换器和复杂编辑器。
- OCR、AI 内容理解、自动标签与语义搜索。
- 完整 PDF 排版增强和整本小说合并，可后续独立评估。
- 定时调度与通知规则扩展，沿用 V1.2 能力。

## 5. 方案对比与选型

| 方案 | 成本 | 复杂度 | 用户体验 | 风险 | 综合评价 |
| --- | --- | --- | --- | --- | --- |
| A：仅强化文件管理器操作 | 低 | 低 | 仍需频繁离开产品 | 产物价值闭环较弱 | 不足 |
| B：本地预览 + 批量管理 + 存储治理 | 中 | 中 | 覆盖采集后的主要使用路径 | 文件安全与格式兼容需控制 | 推荐 |
| C：建设完整内容管理与云同步平台 | 高 | 高 | 能力广但超出当前定位 | 权限、同步冲突和部署复杂 | 本期不做 |

## 6. 功能需求与验收标准

### V1.3-FR-01 视频预览（Must）

支持浏览器可解码的本地 MP4 预览，展示文件大小、路径和缺失状态；不支持格式提供外部打开或打开目录。

- Given 产物为文件存在且浏览器支持的 MP4，When 用户打开预览，Then 可播放、暂停、拖动进度并查看当前文件路径。
- Given 产物为 `.ts` 或浏览器不支持编码，When 打开预览，Then 明确说明不支持在线预览，不显示空白播放器，并提供打开目录。
- Given 视频文件在预览期间被外部删除，When 播放失败，Then 状态更新为缺失并停止重复加载。

### V1.3-FR-02 文字与 PDF 预览（Must）

文字按 UTF-8 读取并分段加载，PDF 使用浏览器可用预览能力；大文件不得一次性阻塞页面。

- Given TXT 文件存在，When 用户打开预览，Then 标题、段落和中文显示正确，长文本按段或分页加载。
- Given PDF 文件存在且浏览器支持，When 打开预览，Then 可查看首页并翻页；失败时提供外部打开或打开目录。
- Given 文件超过预览大小上限，When 用户继续，Then 仅加载允许范围并提示“仅预览部分内容”，不得伪装为完整文件。

### V1.3-FR-03 图片图集预览（Must）

图集以缩略图和单图视图展示，保持原始顺序，支持懒加载与失败项定位。

- Given 图集目录及图片存在，When 打开预览，Then 按序号展示缩略图，点击可查看大图与序号。
- Given 部分图片缺失或损坏，When 加载图集，Then 其他图片仍可查看，失败项明确标记并可关联任务日志。
- Given 图集图片数量较多，When 滚动浏览，Then 按需加载，不在首屏一次性读取全部原图。

### V1.3-FR-04 批量重下与删除（Must）

支持对筛选结果中的已选产物批量操作；仅失败或缺失且可回溯任务的产物允许重下。

- Given 用户选择包含成功与失败产物的混合集合，When 点击批量重下，Then 系统列出可重下与不可重下数量，仅提交符合条件项。
- Given 用户点击批量删除，When 进入确认页，Then 显示产物数量、文件总大小、是否包含目录以及不可恢复提示，确认后执行。
- Given 批量执行中部分失败，When 查看结果，Then 返回逐项成功/失败原因，不把整批标记为全部成功。

### V1.3-FR-05 产物清单导出（Should）

支持导出当前筛选或已选产物为 UTF-8 CSV / JSON，字段包含名称、类型、数据源、分类、状态、大小、路径、指纹和时间。

- Given 用户选择导出当前筛选，When 下载文件，Then 导出范围与筛选口径一致，并明确总条数。
- Given 产物路径或 URL 含敏感信息，When 配置导出字段，Then 用户可取消敏感字段；默认不包含脚本、Webhook 或凭据。
- Given 导出量较大，When 生成文件，Then 采用分页或流式生成，避免一次性将全部记录加载到前端内存。

### V1.3-FR-06 内容指纹与同名冲突策略（Must）

重复判断结合规范化来源 URL 与内容指纹；同名同指纹默认跳过，同名不同指纹默认保留新版本，禁止继续无声覆盖。

- Given 同一来源且内容指纹未变化，When 再次采集，Then 默认记为去重跳过，不新增重复文件，并关联已有产物。
- Given 目标路径同名但内容指纹不同，When 使用默认策略，Then 生成不覆盖原文件的新版本名称，并保留两个产物的溯源关系。
- Given 用户选择“替换”策略，When 新内容已完整写入并校验成功，Then 原子替换旧文件；失败时保留旧文件和错误日志。
- Given 内容发生变化，When 用户查看历史产物，Then 可识别新版与旧版关系及各自创建时间。

### V1.3-FR-07 文件缺失检测与修复（Should）

打开产物页或预览时校验文件存在性；支持按目录重新定位，不仅依赖单次手动刷新。

- Given 文件被外部移动或删除，When 用户查看产物，Then 状态为 missing，禁用无效播放入口并提供重下或重新定位。
- Given 用户选择新的文件/目录位置，When 系统校验名称、类型和可读性，Then 更新产物路径并记录修复审计。
- Given 重新定位后的文件指纹与原记录不同，When 用户确认关联，Then 明确提示内容已变化，不静默覆盖原指纹。

### V1.3-FR-08 存储占用看板（Must）

按内容类型、数据源和目录展示产物大小、文件数量、缺失大小、临时占用和可清理候选。

- Given 用户打开存储看板，When 扫描完成，Then 总占用与各类别之和一致，并显示扫描时间与输出根目录。
- Given 扫描期间文件变化，When 展示结果，Then 标记为扫描时点快照，允许手动刷新，不宣称实时精确。
- Given 产物目录不可访问，When 扫描，Then 该目录显示失败原因，其他目录结果仍可使用。

### V1.3-FR-09 清理规则预检与执行（Must）

默认支持清理超过保留期限的临时目录和明确失败且无效的中间产物；正式成功产物不默认纳入自动清理。

- Given 用户配置清理条件，When 点击预检，Then 展示候选路径、数量、总大小、最老/最新时间和排除项。
- Given 候选文件属于 pending/running/paused 活跃批次，When 生成清理清单，Then 必须排除并说明原因。
- Given 用户确认执行，When 清理完成，Then 返回实际释放空间与逐项失败原因，并写入审计日志。
- Given 清理规则为周期执行，When 每次执行前，Then 重新计算候选，禁止复用旧预检清单直接删除。

### V1.3-FR-10 批量操作审计与本地使用指标（Must）

记录操作者为本机用户、操作类型、筛选快照、选中 ID、确认时间、结果和失败原因，不记录文件正文。

- Given 用户完成批量删除或清理，When 查看审计记录，Then 可追溯到影响范围和逐项结果。
- Given 用户仅预览或导出，When 统计产物使用，Then 按本地产物 ID 去重，不上传文件内容或完整敏感路径。
- Given 用户关闭产品统计，When 继续使用核心功能，Then 预览、删除和导出不受影响，仅停止新增使用指标。

## 7. 核心流程与状态规则

### 7.1 产物使用主流程

筛选产物 → 预览确认 → 选择单条/批量操作 → 查看结果 → 导出清单或进入修复。

### 7.2 同名与版本规则

- 同 URL、同指纹：默认跳过并关联已有成功产物。
- 同路径、不同指纹：默认保留版本；替换必须在新文件完整成功后原子执行。
- 文件写入中：使用 `.part` 与临时目录，未校验完成前不得替换旧正式文件。
- 外部文件变化：标记缺失或内容变化，不自动修改历史指纹。

### 7.3 清理状态

`预检中 → 待确认 → 执行中 → 成功 / 部分成功 / 失败 / 已取消`；预检结果仅用于展示，执行前必须重新校验活跃任务与文件状态。

## 8. 数据与本地埋点需求

### 8.1 数据调整建议

- 产物补充内容指纹、版本组 ID、版本号、来源产物 ID 与路径更新时间。
- 批量操作与清理任务持久化操作类型、筛选快照、候选数量、确认信息和逐项结果。
- 清理规则包含保留期限、适用目录、是否周期执行与最近预检/执行时间。
- 存储扫描结果可按扫描批次缓存，但必须记录扫描时点与失败目录。
- 既有同名文件不得在历史迁移中擅自合并或删除；仅补充可确定的元数据。

### 8.2 事件口径

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `artifact_previewed` | 首屏或首帧加载结束 | 类型、成功/失败、是否支持格式、耗时 |
| `artifact_batch_action_completed` | 批量操作结束 | 操作类型、选中数、成功数、失败数 |
| `artifact_manifest_exported` | 清单导出完成 | 格式、范围、条数、字段集合 |
| `artifact_conflict_detected` | 写入前发现同名 | 同指纹/不同指纹、采用策略 |
| `artifact_relinked` | 缺失文件重新定位成功 | 类型、指纹是否变化 |
| `storage_cleanup_completed` | 清理进入终态 | 候选数、删除数、释放字节、失败数 |

指标不得上传正文、脚本、完整敏感 URL 或文件内容；本地审计保留期限建议默认 180 天，允许用户调整。

## 9. 非功能、安全与合规要求

- 预览接口必须限制在已登记产物路径或用户明确授权的新路径内，防止通过路径参数读取任意本地文件。
- 路径校验需处理符号链接、`..`、大小写与 Windows 路径差异，不能只依赖字符串前缀。
- 大文件采用 Range/分段读取；图片懒加载；清单导出避免全量内存驻留。
- 批量删除与清理默认小批执行并返回逐项结果；活跃任务文件必须排除。
- 替换与清理不得直接覆盖唯一旧文件；失败时保留原产物和可诊断日志。
- 产物内容可能包含第三方版权材料，预览、导出与分享前由用户确认使用权限。

## 12. 上线验证与需求追踪

- 三类内容分别验证正常预览、不支持格式、大文件、部分缺失与外部删除。
- 验证同指纹跳过、同名不同指纹保留版本、替换失败保留旧文件。
- 批量操作覆盖混合状态、部分失败、取消和重复提交。
- 清理覆盖预检后文件变化、活跃任务排除、周期执行重新计算候选与审计。
- 进行路径穿越、符号链接和未授权目录访问测试。
- 使用建议的大样本数据集验证预览与导出性能；具体规模在性能评审时确认，不虚构当前结果。

## 13. 待确认问题

1. 同名不同指纹默认采用“保留版本”是否符合既有用户预期；升级时需明确从旧“覆盖”策略切换。
2. 批量删除是否提供系统回收站选项；若平台能力不一致，需明确降级与二次确认。
3. 临时目录默认保留期限沿用现有 24 小时，正式失败产物是否允许纳入清理需单独确认。
4. 存储看板采用手动扫描还是周期扫描；建议默认手动，避免大目录频繁 IO。
5. 本地审计保留 180 天为建议值，是否允许用户完全清空审计记录。
