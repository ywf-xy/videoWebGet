# CrawlerHub V1.1 需求分析：首次配置激活

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1（评审稿） |
| 产品版本 | V1.1 |
| 编写日期 | 2026-10-25 |
| 文档类型 | 版本需求分析，非开发排期承诺 |
| 需求来源 | 现有 PRD、架构文档、测试报告及 2026-10-25 产品迭代分析 |
| 核心主题 | 配得成：降低首个数据源配置与首个有效产物的获得门槛 |

## 1. 背景与问题定义

V1.0 已具备数据源管理、三种采集策略、任务控制、日志与产物归档能力，但新用户首次配置仍需要理解 JSON、CSS 选择器或 Python 脚本。当前“零命令行”主要体现在任务执行阶段，尚未覆盖数据源配置阶段。

本版本需要解决的不是“增加更多解析能力”，而是缩短从“我有一个目标网址”到“我得到一个可用产物”的路径。

### 1.1 现状证据

- `SourceFormDrawer.vue` 以 JSON 文本配置选择器，自定义脚本作为高级能力。
- 脚本试运行需要保存数据源后发起，新建与测试被拆成两个阶段。
- `VisualCreateView.vue` 当前为能力预告，不提供可视化配置。
- 现有解析预览主要回显字段与前 5 条结果，未覆盖真实下载、转码与落盘验证。

### 1.2 关键假设

- 主要目标用户为个人及轻技术用户，而非专业爬虫工程师。
- 静态列表页和常规详情页足以覆盖第一阶段激活验证；登录、验证码、动态签名和 DRM 不在本版本范围。
- 当前没有真实激活漏斗基线，所有目标值均为建议值，需在灰度后校准。

## 2. 版本目标与成功指标

### 2.1 产品目标

1. 用户不手写 JSON 或 Python，也能完成常规静态站点的数据源配置。
2. 用户在正式批量采集前，可以验证“网址可访问、字段能解析、单条能落盘”。
3. 失败时能够区分网络、选择器、字段、下载、转码和磁盘问题，并获得下一步建议。
4. 既有数据源、JSON 配置和自定义脚本保持兼容。

### 2.2 核心指标

| 指标 | 定义与口径 | 建议目标 | 排除项与说明 |
| --- | --- | --- | --- |
| 首次产物成功率 | 首次创建数据源后 30 分钟内产生至少 1 个成功且文件存在的产物的本地用户实例数 ÷ 首次创建数据源的本地用户实例数 | 基线建立后提升；建议灰度目标 ≥60% | 仅删除草稿、未启动试采的实例仍计入分母；目标值为建议，非现状 |
| 首次有效产物时长 | 首次点击“新增数据源”到首个有效产物成功的时间中位数 | 建议 P50 ≤15 分钟 | 用户离开页面的时间仍计入；按本地安装实例去重 |
| 配置向导完成率 | 完成“保存并进入工作页”的向导数 ÷ 启动向导数 | 先建立基线 | 自动保存后放弃不计为完成 |
| 试采成功率 | 成功试采次数 ÷ 发起试采次数 | 先按内容类型分别观察 | 用户主动取消不计入分母 |
| 配置错误可恢复率 | 解析或试采失败后 30 分钟内修改并成功试采的会话数 ÷ 失败会话数 | 先建立基线 | 同一会话重复失败只计一次 |

> 最小数据能力：本版本必须提供本地激活漏斗看板，至少展示“启动向导—解析成功—试采成功—正式采集成功”四个节点；默认仅保存在本机，可关闭。

## 3. 目标用户与核心场景

| 用户 | 核心诉求 | 典型场景 |
| --- | --- | --- |
| 轻技术采集者 | 不写代码完成常规站点配置 | 输入列表页地址，通过表单配置字段并试采一条 |
| 内容运营 | 在批量任务前确认结果是否符合预期 | 预览标题、正文或图片，确认目录与文件可用 |
| 技术维护者 | 保留高级配置能力并提高排查效率 | 在表单模式与 JSON/脚本模式间切换，查看结构化错误 |

### 用户故事

- 作为轻技术采集者，我希望按字段填写配置并立即预览，以便不需要理解 JSON 也能完成数据源创建。
- 作为内容运营，我希望先试采一条并查看真实产物，以便避免批量生成错误文件。
- 作为技术维护者，我希望继续使用 JSON 和脚本，以便处理复杂站点并迁移既有配置。

## 4. 需求范围

### 4.1 本版本包含

- 分步数据源配置向导与草稿自动保存。
- 选择器配置表单化，保留 JSON 与 Python 高级模式。
- 网址连通性检查、解析预览与字段完整性检查。
- 单条真实试采，覆盖下载、转码、落盘与产物登记。
- 结构化错误诊断与修复建议。
- 声明式示例模板与本地激活漏斗。
- 既有数据源兼容与数据库迁移。

### 4.2 本版本不包含

- 完整浏览器内嵌、点选元素和自动识别所有页面结构。
- 登录态托管、验证码处理、动态签名、DRM 或访问控制绕过。
- 定时调度、通知和全局任务中心，归入 V1.2。
- 产物批量管理与存储治理，归入 V1.3。
- 多用户、权限、云端模板市场和多租户。

## 5. 方案对比与选型

| 方案 | 成本 | 复杂度 | 用户体验 | 风险 | 综合评价 |
| --- | --- | --- | --- | --- | --- |
| A：直接建设完整点选式可视化创建 | 高 | 高 | 理论上较低门槛 | 浏览器兼容、动态页面和安全边界复杂 | 暂缓 |
| B：表单化配置 + 解析预览 + 单条试采 | 中 | 中 | 能覆盖常规站点，同时保留高级模式 | 仍需理解基本字段含义 | 推荐 |
| C：仅增加文档和 JSON 示例 | 低 | 低 | 对轻技术用户改善有限 | 激活瓶颈仍然存在 | 不作为主方案 |

推荐 B。它直接复用现有解析器和执行链路，能够先验证激活问题；若 V1.1 后常规静态站点的首次产物成功率仍不足，再评估点选式创建。

### 方向级 RICE（估算）

Reach=5（1–5 相对触达）、Impact=3、Confidence=80%、Effort=1.0 人月（估算），RICE=`5×3×0.8÷1.0=12.0`。该分值用于版本间排序，不代表真实用户规模或排期。

## 6. 功能需求与验收标准

### V1.1-FR-01 分步配置向导（Must）

向导包含“基本信息 → 字段配置 → 解析预览 → 单条试采 → 完成”五步；允许返回修改，已填内容不得丢失。

- Given 用户点击“新增数据源”，When 进入向导并完成基本信息，Then 系统保留当前步骤和已填内容，并明确下一步操作。
- Given 用户已完成字段配置，When 返回上一步再前进，Then 配置、预览结果与错误状态按最新输入重新计算，不提交旧配置。
- Given 用户关闭向导，When 再次打开同一草稿，Then 可继续编辑或明确放弃草稿。

### V1.1-FR-02 基础信息与环境预检（Must）

必填项沿用名称、类型、主地址；在试采前检查输出目录可写性、视频场景的 ffmpeg 可用性和网络地址格式。

- Given 输出目录不可写，When 用户进入试采步骤，Then 系统阻止试采并显示具体路径与修复入口。
- Given 视频类型且 ffmpeg 不可用，When 用户发起试采，Then 系统明确说明只能验证解析或按现有降级策略处理，不得伪装为 MP4 试采成功。
- Given 主地址不是合法 HTTP/HTTPS URL，When 用户继续，Then 在字段旁显示错误且不发起网络请求。

### V1.1-FR-03 选择器表单化与高级模式（Must）

按内容类型提供列表地址、列表项、链接、标题、正文、视频地址、图片地址、分页等适用字段；字段值支持现有 `css@attr` 规则。

- Given 用户填写合法选择器，When 保存数据源，Then 生成的 `config_json` 与现有内置解析器契约一致。
- Given 既有数据源包含 JSON 配置，When 在表单模式打开，Then 已支持字段正确回填；无法映射的字段保留在高级 JSON 中且不得静默删除。
- Given 用户启用自定义脚本，When 切换到高级模式，Then 既有脚本编辑、入口设置和语法校验仍可使用。

### V1.1-FR-04 连通性检查与解析预览（Must）

用户无需先保存数据源即可测试当前配置；预览展示解析数量、前 5 条样例、字段完整性和实际请求地址。

- Given 当前配置尚未保存，When 用户点击“解析预览”，Then 后端使用本次表单快照执行测试，不创建正式数据源。
- Given 页面可访问但列表为空，When 预览完成，Then 状态为“未解析到条目”，并突出列表项、链接和分页字段的检查建议。
- Given 样例缺少标题或详情地址，When 预览展示，Then 对应行和字段显示缺失原因，不允许将其视为完整成功。

### V1.1-FR-05 单条真实试采（Must）

从预览样例中选择一条执行真实任务，验证下载、格式转换、目录生成和产物登记；试采不推进正式增量游标。

- Given 解析预览至少有一条完整样例，When 用户选择一条并试采，Then 系统创建 `trigger_type=preview` 的批次并展示与正式采集一致的进度与日志。
- Given 试采成功，When 查看结果，Then 可看到产物名称、类型、大小、落盘路径及打开目录入口，且文件实际存在。
- Given 同一数据源随后发起正式增量采集，When 计算游标，Then 不得因试采而跳过未正式采集的内容；试采与正式采集统计分列。

### V1.1-FR-06 结构化错误诊断（Must）

将错误分为网址/网络、选择器、字段缺失、下载、转码、磁盘和脚本七类，保留原始错误码供排查。

- Given 试采失败，When 用户查看结果，Then 页面展示失败阶段、人话原因、建议动作、相关字段和查看日志入口。
- Given 错误属于不可重试的脚本或 403/404，When 展示操作，Then 不建议无脑重试，而是引导修改配置或检查授权与地址。
- Given 同一错误连续出现，When 用户再次打开向导，Then 保留最近一次诊断摘要，直到输入变更或重新测试。

### V1.1-FR-07 保存与后续动作（Must）

试采成功后可以保存并进入对应工作页；用户也可仅保存配置，稍后采集。

- Given 试采成功且数据源未保存，When 用户点击“保存并开始采集”，Then 数据源只创建一次，随后进入工作页，不自动重复创建试采批次。
- Given 保存发生重名冲突，When 返回向导，Then 已测配置与预览结果不丢失。
- Given 数据源创建成功，When 用户选择“稍后采集”，Then 返回数据源详情并明确下一步入口。

### V1.1-FR-08 声明式示例模板（Should）

提供覆盖三类内容的示例模板；模板仅包含说明和声明式配置，不默认携带可执行脚本。

- Given 用户选择示例模板，When 加载配置，Then 页面明确示例网址需替换，并填充可编辑字段。
- Given 模板包含未知字段或版本不兼容，When 导入，Then 阻止覆盖现有配置并显示不兼容字段。
- Given 导入内容包含脚本，When 用户确认加载，Then 显示信任提示；本版本不自动执行第三方脚本。

### V1.1-FR-09 既有数据与草稿迁移（Must）

升级不得破坏既有数据源、配置、任务和产物；向导草稿与正式数据源分离。

- Given 旧版本数据库升级，When 迁移完成，Then 既有数据源仍可由原工作页和编辑页使用。
- Given 草稿超过保留期限，When 系统清理，Then 只清理未提交草稿，不删除正式数据源或任务。
- Given 迁移失败，When 应用启动，Then 保留原数据库备份并给出可恢复提示，不反复覆盖原库。

## 7. 关键流程与状态

主流程：新增数据源 → 填写基础信息 → 配置字段 → 解析预览 → 选择样例试采 → 查看真实产物 → 保存并开始/稍后采集。

分支与异常：

- 解析成功但试采失败：保存为草稿，定位到失败阶段，不推进游标。
- 解析为空：允许返回字段配置，不允许进入真实试采。
- 试采成功后修改关键配置：原试采结果标记为“非当前配置”，需重新试采。
- 高级模式与表单模式切换：字段冲突时以当前编辑快照为准，并在提交前显示变更摘要。
- 后端离线：保留本地编辑内容，恢复连接后由用户主动重试，不自动重复提交。

## 8. 数据与本地埋点需求

### 8.1 数据调整建议

- `crawl_batch` 增加 `trigger_type`：`manual / preview`；V1.2 可扩展 `schedule`。
- 试采批次记录配置快照哈希，用于识别“结果是否对应当前配置”。
- 向导草稿独立存储，包含内容类型、当前步骤、表单快照、更新时间和保留期限。
- 既有表结构变更同步更新模型与幂等迁移，升级前备份数据库。

### 8.2 事件口径

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `source_wizard_started` | 首次进入向导 | 内容类型、入口 |
| `source_parse_tested` | 解析预览结束 | 成功/为空/失败、错误分类、耗时、配置哈希 |
| `source_preview_completed` | 单条试采进入终态 | 成功/失败、内容类型、错误分类、耗时、产物是否有效 |
| `source_created` | 正式数据源创建成功 | 创建模式、是否使用模板、是否已试采 |
| `first_formal_batch_completed` | 首个正式批次进入终态 | 成功/失败、与试采的时间间隔 |

埋点不得记录完整 URL 查询参数、正文、脚本内容或文件内容；如需定位，仅记录脱敏主机名、错误码和配置哈希。

## 9. 非功能、安全与合规要求

- 解析预览接口在常规本地测试环境下 P95 响应目标 ≤30 秒；超时必须可取消，具体阈值按站点网络条件校准。
- 向导编辑和模式切换不得发起无提示的批量网络请求。
- 试采默认仅 1 条，复用全局并发限制与请求频率约束。
- 未保存的测试配置仅在本次测试所需内存与临时记录中保存，日志不得输出敏感查询参数。
- 自定义脚本继续遵循“本机可信用户”边界，不将受限命名空间宣传为安全隔离。
- 示例与模板仅面向公开或已获授权内容；不提供验证码、DRM 或访问控制绕过指引。

## 12. 上线验证与需求追踪

- 三类内容各完成至少一条“新建—预览—试采—正式采集”端到端用例。
- 覆盖空列表、字段缺失、网络失败、脚本失败、ffmpeg 缺失、目录不可写与配置修改后重试。
- 验证试采不推进游标、不重复创建数据源、不混入正式采集量。
- 验证旧 JSON 与脚本配置往返无损，旧库升级后数据可查可用。

| 需求 | 主要设计/实现落点 | 核心测试 | 状态 |

| V1.1-FR-01～03 | 配置向导、数据源表单、配置转换 | 表单/JSON 往返、草稿恢复 | 待评审 |
| V1.1-FR-04～06 | 解析测试、试采、诊断 | 三类内容端到端与失败分类 | 待评审 |
| V1.1-FR-07～09 | 保存、模板、迁移 | 防重复提交、旧库升级 | 待评审 |

## 13. 待确认问题

1. 首次产物成功率的统计窗口采用 30 分钟是否适合真实用户；灰度后按行为分布调整。
2. 试采产物默认保留还是由用户选择清理；默认建议保留并明确标记“试采”。
3. 草稿保留期限建议为 30 天，是否需提供用户可配置项。
4. 声明式模板的首批示例来源与授权证明由产品维护者确认。
