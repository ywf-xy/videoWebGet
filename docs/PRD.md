## 1. 产品概述与目标

### 1.1 一句话定位

面向个人与小团队的**本地化通用爬虫工作台**：以「数据源 + 策略」为统一抽象，把视频 / 文字 / 图片三类站点采集、任务调度、产物归档收敛到一套可视化界面里，零命令行完成从配置到落盘。

### 1.2 核心价值

| 编号 | 价值点 | 说明 |
| --- | --- | --- |
| V-01 | 三类内容一套模型 | 视频、文字、图片共用「数据源 → 策略 → 任务 → 产物」主链路，只有解析脚本与落盘规则不同，学习成本只付一次 |
| V-02 | 增量可控，不重复爬 | 三种策略天然带回溯游标（条数 / 页码 / 日期），配合历史成功记录去重，重复劳动降到最低 |
| V-03 | 过程可观测、可干预 | 任务进度、线程占用、日志、健康度全部可视化；支持暂停与重试，不怕跑一半出错 |
| V-04 | 视频下载开箱可用 | 内置 HLS(m3u8) 分片下载 + 自动转 MP4，无需额外装工具链即可得到可播放文件 |
| V-05 | 产物按规则自动归档 | 目录与文件名由规则统一生成，产物可直接被本地播放器 / 阅读器消费，免手工整理 |

### 1.3 本期范围边界

| 范围内 | 范围外（本期不做） |
| --- | --- |
| 单机单用户运行 | 多租户、账号体系、权限管理 |
| 手动维护数据源 + 脚本 | 可视化拖拽式创建数据源（仅预留入口） |
| 三类内容采集 | 通用浏览器自动化（验证码、登录态托管） |
| 本地文件系统落盘 | 对象存储 / 云端同步 |
| 手动触发爬取 | 定时调度（预留，P2） |

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 个人采集者 | 有明确目标站点，懂一点技术但不想写调度代码 | 配好数据源就能稳定批量下载，出错能看懂原因 |
| 小团队内容运营 | 需要周期性收集素材（视频/文章/图片） | 增量采集、产物按规则归档、可交付给下游 |
| 技术型维护者 | 会写 Python 解析脚本 | 脚本可插拔，数据源可导入导出，方便备份与迁移 |

### 2.2 典型场景

**场景 A：追更小说 / 专栏（文字类）**
用户维护一个小说站数据源，选择「按日期」策略并指定区间，平台先抓取章节列表，再按设置的线程数批量抓正文，自动过滤已成功章节，最终按 `数据源/分类/小说名/章节名.txt` 落盘。跑到一半发现站点限流，点「暂停」，10 分钟后「恢复」，已完成的章节不重复下载。

**场景 B：批量存档视频（视频类）**
用户有 3 个同站点的备用域名（主站偶发不可用）。在视频列表页点「开始爬取」，选「按指定条数 50」，工作页展示上次爬到第 1200 条、第 60 页。平台先解析列表拿到 50 条详情页地址，生成 50 个任务，按 4 线程并发下载 m3u8 分片并自动转 MP4；2 条失败，在任务列表点「重试」补齐。

**场景 C：素材图库收集（图片类）**
用户按分页策略抓取图集站第 1~20 页，图片按 `数据源/分类/日期/图集名/` 落盘。次日打开「产物」页，按数据源 + 日期 + 状态=失败 过滤，定位到 3 张失败图片并排查。

## 3. 术语表

| 术语 | 英文 / 字段 | 定义 |
| --- | --- | --- |
| 数据源 | DataSource | 一个站点/栏目的采集配置单元，包含名称、类型、主页地址、备用地址列表、解析脚本、分类、状态 |
| 备用网址 | alt_urls | 同一数据源的可替换入口地址列表，主地址不可用时切换 |
| 分类 | category | 数据源下的二级归类（如「科幻」「古装」），参与产物目录命名 |
| 策略 | strategy | 决定「爬多少、从哪开始」的规则，本期三种：按条数 / 按分页 / 按日期 |
| 游标 | cursor | 某个数据源上一次采集到的位置（条序号、页码、最新日期），用于增量 |
| 任务 | Task | 针对**单条内容**（一个视频、一章文字、一组图片）的最小采集单元，是本平台并发与重试的基本粒度 |
| 任务结果 | TaskResult | 任务采集完成后的结构化产出，包含落盘路径、大小、耗时、状态 |
| 任务日志 | TaskLog | 任务执行过程的分级日志（INFO/WARN/ERROR），按任务聚合 |
| 产物 | Artifact | 任务成功后生成的文件实体（mp4 / txt / pdf / 图片集合），是「产物」页的展示对象 |
| 健康度 | Health | 数据源可用性评分（0-100），由近期任务成功率与最近成功时间综合计算 |
| 线程数 | max_workers | 全局并发上限，在设置页配置，爬虫引擎按此值限制同时运行的任务数 |
| 工作页 | Workbench | 单个数据源的爬取操作页（列表页的下钻页），承载进度展示与策略表单 |

| P0-21 | 数据源页 | 数据源查看与手动维护：新增、编辑、删除、启用/停用 | ① 新增必填项校验通过后可保存并出现在列表；② 编辑后列表即时更新；③ 删除前二次确认，删除后关联任务仍可查（保留历史）；④ 停用后该数据源不出现在三类列表页的可采集列表中 |
| P0-22 | 数据源页 | 数据源导入：支持上传 JSON（及 CSV）文件批量导入 | ① 上传合法 JSON 后导入成功并返回「成功 N 条 / 失败 M 条」；② 字段缺失或类型错误的行被跳过并给出逐行错误原因；③ 重复数据源（同 name + homepage_url）默认跳过不覆盖，除非勾选「覆盖同名」 |
| P0-23 | 数据源页 | 数据源导出：支持导出为 JSON 文件 | ① 导出文件为 UTF-8 JSON 数组；② 可直接被 P0-22 导入且字段无损（往返一致）；③ 支持勾选部分导出与全量导出 |

## 7. 三种获取策略的业务规则

### 7.1 策略定义与字段

| 策略 | 语义 | 关键输入 | 游标来源 | 适用场景 |
| --- | --- | --- | --- | --- |
| S1 按指定条数 | 从「上次记录之后」开始，取 n 条 | n（条数） | 上次批次的最后条目序号 / 指纹 | 追更、小批量试跑 |
| S2 按分页 | 从指定起始页开始，连续取 pages 页 | start, pages | 上次批次的最后页码（作为默认 start-1） | 首次全量、按期归档 |
| S3 按日期 | 取日期区间内的全部条目，并过滤历史已成功项 | date_from, date_to | 历史成功记录的指纹集合 | 增量补采、按时间对账 |

### 7.2 边界情况处理

| 场景 | 处理规则 | 用户可见反馈 |
| --- | --- | --- |
| S1 首次爬取（无历史游标） | 视为游标 = 0，从列表第 1 条开始取 n 条 | 工作页显示「暂无历史记录，本次将从起点开始」 |
| S1 n 大于剩余总数 | 取到列表末尾为止，任务数 = 实际剩余条数；批次状态 success_with_warning | 提示「请求 n 条，实际获取 m 条（已到列表末尾）」 |
| S1 列表为空 | 不生成任务，批次状态 success，任务数 0 | 「列表解析结果为空，请检查解析脚本或网址」 |
| S1 游标之后不足 n 条但列表可翻页 | 自动继续翻下一页补足，直到取满 n 或列表结束 | 进度显示「已翻至第 K 页」 |
| S2 起始页大于总页数 | 不生成任务，批次状态 failed（error_code=PAGE_OUT_OF_RANGE） | 「起始页 X 超出总页数 Y，请调整」 |
| S2 页数越界（start+pages-1 > 总页数） | 截断到最后一页，成功并记 WARN | 「请求 pages 页，实际获取 k 页（已到最后一页）」 |
| S2 中间某页为空 | 视为列表结束，停止翻页，已解析条目照常建任务 | 「第 X 页无数据，采集提前结束」 |
| S2 某页请求失败 | 重试（P1-06）后仍失败 → 该页标记 skipped，继续后续页；批次 success_with_warning | 日志 ERROR 记录页码与原因 |
| S3 区间内条目无日期字段 | 该条不参与日期过滤，默认保留并记 WARN（假设：脚本应提供 date 字段） | 日志 WARN「条目缺少日期字段，已按保留处理」 |
| S3 条目日期命中历史成功指纹 | 跳过，计数为 skipped，不生成任务 | 统计条显示「跳过 N 条（已采集过）」 |
| S3 date_to 为今天且含未发布条目 | 仅处理列表页已出现的条目，不做未来预测 | 无特殊提示 |
| S3 区间跨度超上限（365 天） | 表单层拦截，不允许提交 | 字段级红字「日期跨度不能超过 365 天」 |
| 任意策略：去重后任务数为 0 | 批次状态 success，任务数 0，不产生空批次记录以外的副作用 | 「没有需要采集的新内容」 |
| 任意策略：同数据源已有运行中批次 | 拒绝新批次（single-flight） | 「该数据源有运行中的批次，请先暂停或等待完成」 |

### 7.3 伪逻辑

```text
# S1 按指定条数
cursor = last_batch.last_index or 0
items, page = [], current_page_from(cursor)
while len(items) < n and page exists:
    parsed = parse_list(page)
    items += [x for x in parsed if x.index > cursor]
    if len(items) >= n: break
    page = next_page(page)
items = dedup(items)[:n]
batch.status = (len(items) < n) ? success_with_warning : success

# S2 按分页
if start > total_pages: raise PAGE_OUT_OF_RANGE
end = min(start + pages - 1, total_pages)
for p in start..end:
    try: items += parse_list(p)
    except: log(ERROR, p); mark_page_skipped(p)
    if is_empty(p): break
if end < start + pages - 1: warn("truncated to last page")

# S3 按日期
items = [x for x in parse_list_all() if in_range(x.date, from, to)]
items = [x for x in items if fingerprint(x) not in success_fingerprints]
skipped = len(candidates) - len(items)

# 公共后置
tasks = build_tasks(items)          # 一条内容 = 一个 task
engine.submit(tasks, max_workers=settings.max_threads)
```

### 7.4 游标更新时机

| 时机 | 是否更新游标 | 说明 |
| --- | --- | --- |
| 批次全部成功 | 是 | 记录 last_index / last_page / last_date |
| 批次部分失败 | 是（仅按成功项推进） | 避免失败项被永久跳过；失败项保留在失败列表供重试 |
| 批次被用户暂停后恢复并完成 | 是 | 同「全部成功」 |
| 批次被用户手动终止（不做本期功能，仅说明） | 否 | 保持上次游标 |
| 阶段一（列表解析）失败 | 否 | 无有效列表即无游标推进 |

## 9. 关键业务规则

### 9.1 产物目录命名规则

| 类型 | 规则模板 | 示例 |
| --- | --- | --- |
| 视频 | `{输出根}/{数据源名}/{分类}/{视频名}.mp4` | `D:/out/某某影视/科幻/星际穿越.mp4` |
| 文字-小说 | `{输出根}/{数据源名}/{分类}/{小说名}/{章节名}.{txt\|pdf}` | `D:/out/某某小说网/科幻/三体/第001章 科学边界.txt` |
| 文字-非小说 | `{输出根}/{数据源名}/{分类}/{yyyy-MM-dd}/{文章名}.{txt\|pdf}` | `D:/out/某新闻站/科技/2026-10-25/AI 芯片发布.txt` |
| 图片 | `{输出根}/{数据源名}/{分类}/{yyyy-MM-dd}/{图集名}/{序号}.{jpg\|png}` | `D:/out/某图库/写真/2026-10-25/夏日/001.jpg` |

补充规则：
1. `分类` 为空时使用 `未分类`。
2. 目录层级缺失时自动逐级创建（mkdir -p 语义）。
3. 图片序号按列表页顺序从 `001` 起，宽度按总数位宽决定（≥3 位）。
4. 日期取任务执行日期（本地时区），非条目发布日期。

### 9.2 文件名 / 目录名清洗规则

| 规则 | 处理方式 |
| --- | --- |
| 非法字符 | `\ / : * ? " < > \|` 及 ASCII 控制字符（0x00-0x1F）替换为 `_` |
| 首尾空白与点 | 去除首尾空格与 `.`（Windows 不允许结尾点） |
| 长度限制 | 单段名称 ≤ 100 字符；超长截断至 92 字符 + `_` + 8 位内容哈希前 8 位 |
| 保留名 | `CON PRN AUX NUL COM1-9 LPT1-9` 前加 `_` 前缀 |
| 空名称 | 替换为 `untitled_{yyyyMMddHHmmss}` |
| 换行/多空格 | 合并为单个空格 |
| 重名 | 本期默认覆盖并写 WARN 日志（去重/版本化见 P2-04） |

### 9.3 并发上限规则

| 规则 | 说明 |
| --- | --- |
| 全局并发 | 单进程线程池，上限 = `max_threads`（默认 4，范围 1-32） |
| 数据源级 single-flight | 同一数据源同一时刻最多 1 个 running 批次；新批次被拒绝 |
| 批内并发 | 任务级并发受全局上限约束，不做数据源级细分配额 |
| m3u8 分片并发 | 单任务内分片并发默认 4，且不得使全局线程占用超过上限（分片下载走独立受限池，上限 = min(4, max_threads)） |
| 动态调整 | 修改 `max_threads` 后，新取任务立即按新值；已运行任务不中断 |
| 超限保护 | 队列长度 > 5000 时拒绝新建批次并提示「待执行任务过多，请先处理现有批次」 |

### 9.4 暂停语义

| 维度 | 定义 |
| --- | --- |
| 生效粒度 | 批次级与任务级；批次暂停 = 批内所有未开始任务不再被调度 |
| 对运行中任务 | 不强制杀线程；在当前原子步骤（当前分片 / 当前章节 / 当前图片）结束后退出，状态从 running 回退为 pending |
| 状态变化 | 批次 → paused；pending 任务保持 pending；running 任务在当前步骤后转 pending |
| 已完成部分 | 已下载分片、已完成章节保留，恢复时复用（断点续传） |
| 恢复 | 批次 → running，从 pending 任务继续，已 success 任务不重复执行 |
| 超时保护 | 暂停后 30s 内活跃线程未归零 → 批次标记 paused_with_warning 并在日志记录残留任务 |
| 限制 | 暂停不释放已完成文件；不提供「取消/终止」语义（本期） |

### 9.5 重试语义

| 维度 | 定义 |
| --- | --- |
| 触发方式 | 手动（单条 / 批量失败重试）；自动（P1，网络类错误） |
| 可重试状态 | 仅 `failed`；`success`、`running`、`pending` 不可重试 |
| 计数 | `attempt_count` 每次执行 +1，手动重试不清零但受 `max_attempts` 约束（默认 3） |
| 自动重试范围 | 连接超时、5xx、分片下载失败、m3u8 解析失败；不重试 404、403、脚本语法错误 |
| 退避 | 间隔 = `base_interval(1s) × 2^(attempt-1)`，上限 30s |
| 幂等 | 重试复用同一 task 记录，覆盖旧 task_result（保留最新），日志追加不覆盖 |
| 批次状态回退 | 有 failed 任务被重试时，批次状态从 success_with_warning 回到 running |

### 9.6 健康度计算规则

```text
if 近 20 次任务数为 0: health = null（未知，灰色）
success_rate = 近 20 次 success 数 / 近 20 次总数
recency = clamp(1 - days_since_last_success / 14, 0, 1)
health = round(100 * (0.7 * success_rate + 0.3 * recency))
分级：>=80 绿(健康) / 60-79 黄(亚健康) / <60 红(异常)
```

### 9.7 m3u8 处理规则

| 步骤 | 规则 |
| --- | --- |
| 解析 | 支持 master playlist（取最高带宽 variant）与 media playlist |
| 加密 | 支持 `EXT-X-KEY` 的 AES-128（按 key URI 拉取密钥，IV 缺省用序号）；SAMPLE-AES / DRM 不支持，任务置 failed 并明确提示 |
| 分片 | 并发下载到临时目录 `{output_root}/.tmp/{task_id}/`，失败分片重试 2 次 |
| 合并 | 按 `EXTINF` 顺序拼接（二进制 concat，不做转码以保证速度） |
| 转换 | 调用 ffmpeg `-c copy` 转封装为 MP4；失败则回退 `-c:v libx264 -c:a aac` 重编码（可配置） |
| 清理 | 成功 moveto 目标路径后删除临时目录；失败保留 24h 便于排查 |
| 依赖检测 | 启动时检测 ffmpeg，缺失时在设置页红字提示，视频任务直接失败并给出安装指引 |
